How a memo gets made

Every example follows the same five stages, and each stage ends with something you can inspect.

  1. 1Sources and numbersA source list and a table of inputs, each marked public, yours or assumed.
  2. 2RecordA dated log with one line per item, its source and its status.
  3. 3Written rulesScores, ratings and rankings that follow rules shown before any result.
  4. 4ReviewA named person’s decision on each result: accept, hold or overrule.
  5. 5MemoOne page with a recommendation, the trade-off, the key uncertainty and the next action.

This is the design pattern. The examples on this site do not all perform every stage, and none of them fetches sources for you.

What the workflow does

It collects or receives the inputs, records each item with a date, a source and a status, applies written rules, runs the calculations and drafts the memo. A gap is logged as a gap, and a conclusion that rests on inference is rated as inference, so it cannot pass for a disclosed fact.

Calculations and scoring use explicit code, so the rules can be inspected and repeated. Where a live build uses a language model to read text, its role is stated and each quote it extracts is checked against the fetched text. The demo and the examples here call no language model.

What the person does

A person chooses the sources and the decisions to track, supplies the real numbers, approves, holds or overrules each result, and makes the decision.

Fixed
The stages, the status labels, a date and a source on every item, gaps logged and never filled, and no release without approval.
Set with you
The topic, the sources, the rating rules, the memo format, the schedule, who reviews and where the memo goes.
